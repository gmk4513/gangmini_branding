## 여기가 원본이다

이 게임은 `gangmini_branding` 저장소의 `game/` 폴더에 산다. 별도 저장소가 없다.

```
gangmini_branding/          ← git 저장소는 여기
├── index.html              브랜딩 페이지
├── data.js                 프로젝트 목록 (이 게임은 #3)
├── covers/
└── game/                   ← 이 폴더. https://gangmini.com/game/ 으로 나간다
```

**고치고 `git push` 하면 Cloudflare Pages 가 30초쯤 뒤에 반영한다.** 빌드 단계가 없다.

> **js 나 css 를 고쳤으면 `index.html` 의 `?v=` 숫자를 함께 올릴 것.**
> Pages 는 js·css 에 `max-age=14400`(4시간) 을 붙인다. 그래서 배포해도 전에
> 들어와 본 사람은 최대 4시간 동안 옛 코드를 받는다. 실제로 배포 직후 폰에서
> 확인하다 옛 화면을 보고 한참 헤맸다.
> `_headers` 로 캐시 정책을 바꿔 보려 했지만 이 프로젝트에서는 설정으로 읽히지
> 않고 그냥 파일로 서빙됐다. 그래서 주소에 붙이는 방식을 쓴다.

한때 `사업IDEA\비프리vs로보트_무한의계단\B_FREE-construction` 에도 같은 복사본이
있었다. 두 곳을 손으로 맞추다 어긋나서 그쪽은 접었다. 그 경로에 폴더가 아직
보이면 옛것이니 건드리지 말 것.

순위표·방문자 집계의 서버 코드는 여기 없다. `gmk4513/bamti-bomb` 저장소의
`server/scores.js` 와 `server/index.js` 다.

## 게임 규칙 (건드리기 전에 알아야 할 것)

- 탑은 지그재그 계단. `S.dirs[i]` = 블록 i-1 → i 방향(+1 오른쪽, -1 왼쪽), `S.cols[i]` = 가로 칸 번호
- 입력은 방향 하나로 수렴한다: `step(dir)`. TURN 버튼 = `step(-facing)`, CLIMB 버튼 = `step(facing)`
- 키보드: **스페이스 = TURN**, **→ = CLIMB**. `e.repeat` 무시(꾹 누르기 방지)
- 플레이어는 `BASE`(30)번 블록에서 시작한다. 시작 지점 아래에도 탑이 있어야 로봇이 딛고 올라온다.
  점수 = `S.idx - BASE`
- 게이지 = 로봇과의 거리(칸). `LEAD_MAX`(14) 이상 못 벌린다. 0이 되면 잡힘

## 튜닝 상수 (js/game.js 상단)

| 상수 | 값 | 의미 |
|---|---|---|
| `LEAD_MAX` / `LEAD_START` | 14 / 14 | 로봇과의 최대·시작 거리(칸). **12.2칸 미만이면 시작하자마자 로봇이 화면에 보인다** |
| `ROBOT_V0` / `ROBOT_K` / `ROBOT_VMAX` | 1.45 / 0.019 / 9.0 | 로봇 속도 = V0 + 층수×K (칸/초), 상한 VMAX |
| `BLOCK_W` / `BLOCK_H` | 102 / 51 | 블록 크기(가상 단위, 화면 세로 = 900 기준) |
| `STEP_X` / `STEP_Y` | 92 / 44 | 한 칸 이동량. **`STEP_Y` > `BLOCK_H` 면 계단이 공중에 뜬다** |
| `CHAR_H` / `ROBOT_H` | 190 / 202 | 캐릭터·로봇 그리기 높이 |
| `HOP_MS` | 95 | 칸 이동 보간 시간(ms) |

난이도 감각(완벽 플레이 기준, 현재 값): 초당 2탭 → 81층/41초, 5탭 → 270층/54초, 8탭 → 475층/60초.
난이도를 바꿨으면 이 수치를 다시 뽑아보고 판단할 것.

## 좌표계

- 캔버스는 **가상 세로 900** 기준으로 그린다. `VW`는 화면 비율에 따라 달라진다(대략 360~560)
- 레이아웃은 전부 비율로 잡혀 있다. **하드코딩된 px 위치를 넣지 말 것.**
  화면 세로 620~900, 가로 360~560 범위에서 겹치지 않는지 확인해야 한다
- 결과 화면의 `SCENE` 객체가 배경 대비 캐릭터 위치를 정한다.
  `figCX`/`figW`를 키우면 배경에 그려진 노인들과 겹친다 (오른쪽 한계 0.578, 위쪽 한계 0.634)

## 절대 깨뜨리면 안 되는 것

1. **`.screen.home` / `.screen.over` 는 `:not(.hidden)` 조건부로만 `display:block`.**
   조건 없이 쓰면 `.screen.hidden{display:none}` 과 우선순위가 같아져서 게임 중에도 홈 화면이 남는다
2. **전체 폭을 덮는 장식 요소에는 `pointer-events:none`.**
   `.home .hero`, `.over .ovtop` 이 그렇다. 빼면 그 아래 버튼이 안 눌린다
3. **벽돌 버튼의 라벨은 `<span>` 안쪽만 바꾼다.** `button.textContent = ...` 로 쓰면 span이 지워지고
   `.brick.p span{color:#000}` 이 날아가 글자가 흰색이 된다. `setLabel(id, text)` 사용
4. **서버에서 읽어온 배열을 그대로 수정하지 말 것.** 복제 후 push/sort

## 순위표 (연결 완료)

`js/leaderboard.js` 의 `MODE='fly'`. 기록은 **Bamti Bomb 서버**에 저장된다.
그 서버는 중계만 해서 CPU 가 놀고, 방문자 숫자를 담으려고 붙여 둔 볼륨도
거의 비어 있어서 순위표를 얹기 좋았다.

```
GET  https://bamti-bomb.fly.dev/api/scores/bfree?limit=100
POST https://bamti-bomb.fly.dev/api/scores/bfree   {name, score}
```

서버 코드는 밤티밤 저장소의 `server/scores.js` 다. 게임별로 board 이름을
나눠 쓰므로, 다음 게임을 만들면 board 만 새로 잡으면 된다.

**Supabase 를 쓰지 않은 이유** — anon 키를 페이지에 박아야 하고, 그 키로 누구나
insert 할 수 있다. 막으려면 결국 Edge Function 을 따로 짜야 한다.
서버가 내 것이면 아래 검사가 전부 서버 안에 남는다.

| 검사 | 값 |
|---|---|
| 점수 상한 | 2000 (완벽 플레이가 475층이라 한참 위. 넘으면 조작) |
| IP 당 저장 | 시간당 30회, 최소 3초 간격 |
| CORS | `gangmini.com`, `localhost:8000` 만 |

**아직 없는 것**: 기록을 지우는 길. 욕설 닉네임이 올라오면 지금은 서버에
직접 들어가 `/data/scores.json` 을 고치는 수밖에 없다. 공개 전에 `STATS_KEY`
로 잠근 삭제 엔드포인트를 하나 두는 게 낫다.

**남은 치팅 여지**: 개발자도구로 `Leaderboard.submit('x', 1999)` 를 부르면
들어간다. 상한과 요청 제한이 걸릴 뿐이다. 진짜로 막으려면 입력 시퀀스를
서버에서 재현해 검증해야 하는데, 그건 이 규모에 과하다.

`MODE='local'` 로 바꾸면 서버 없이 기기별 저장으로 돌아간다. 개발할 때 쓴다.

## 방문자 집계

이 페이지는 Cloudflare 가 내보내므로 순위표 서버가 방문을 알 수 없다. 그래서
`index.html` 이 열릴 때 `bamti-bomb.fly.dev/beacon.gif?s=bfree` 를 한 번 부른다.
`<img>` 라 CORS 가 필요 없고, 실패해도 게임에는 영향이 없다.

숫자는 순위표와 같은 자리에서 본다 — `bamti-bomb.fly.dev/stats?key=…`

  공개 배포 전에 사용 권리를 확인할 것
