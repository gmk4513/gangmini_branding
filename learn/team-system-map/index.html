시스템의 큰 그림
— 버그가 어느 층에 있나

직무 팀에서 일하기 디버깅 빌드 캐시 R8 2026.10.28

팀에서 일하기 시리즈 3번이다. AI 는 코드를 잘 쓰지만, 버그가 났을 때 "이건 코드 문제가 아니라 캐시 문제다"를 먼저 짚어 주지는 않는다. 물어보는 내가 어디를 봐야 할지 알아야 한다. 그게 없으면 AI 가 엉뚱한 곳을 고쳐도 그대로 믿게 된다.

내가 쓰는 지도는 다섯 층이다. 내가 쓴 코드가 사용자 화면에 닿기까지 거치는 단계이고, 버그는 반드시 이 중 한 층에 있다.

② 빌드 — 릴리스에서만 죽는 앱

학창시절 다이어리에 R8(안드로이드 코드 줄이기·난독화)을 켰을 때 가장 걱정한 게 이 층이다. R8 은 "어디서도 부르지 않는 코드"를 지우고 이름을 a, b 처럼 짧게 바꾼다. 그런데 React Native 는 네이티브 모듈을 문자열 이름으로 찾아 부른다. R8 눈에는 그 호출이 안 보인다.

  • 증상: 개발 중엔 멀쩡하다. 릴리스 빌드에서만 켜자마자 죽거나, 특정 기능만 조용히 안 된다. 개발 빌드에선 R8 이 안 돌기 때문이다.
  • 막는 법: 라이브러리가 싣고 오는 keep 규칙("이 이름은 바꾸지 마")이 있다. 그래도 빠진 게 없는지 릴리스 빌드를 직접 깔아 그림판·DB 저장·서버 호출·결제 화면을 눌러 봤다.
  • 같은 층의 다른 문제: R8 단계에서 빌드 도구의 메모리가 모자라 OutOfMemoryError: Metaspace 로 빌드 자체가 죽었다. 코드는 한 줄도 틀리지 않았다.

③ 실행 — 아이폰에서만 안 나는 소리

스쿠터 게임을 PC 로만 확인하고 올렸는데, 폰으로 해 보니 엔진 소리는 나는데 캐릭터 목소리가 하나도 안 났다. 코드는 PC 에서 잘 돌았으니 ① 은 아니다.

원인은 아이폰 사파리의 정책이었다. <audio>.play() 는 사람이 화면을 누른 그 순간에만 허락된다. 대사는 NPC 에게 다가가거나 아이템을 먹을 때, 즉 아무것도 안 누른 순간에 나오니 전부 막혔다. 엔진 소리는 처음부터 Web Audio 였고, 출발 버튼을 누를 때 한 번 깨워 둬서 계속 났다. 목소리도 Web Audio 로 옮겨서 고쳤다.

같은 층의 다른 예. ES 모듈로 만든 게임은 파일을 더블클릭해 열면 브라우저가 막는다. 실행 환경(file://)의 규칙이다. 자세한 건 ES 모듈과 클래식 스크립트에 적었다.

④ 네트워크 — 첫 요청만 느리다

이 사이트의 원칙 중 하나가 "정적으로 가능하면 정적으로"다. 이유가 이 층에 있다. Fly.io 서버에 유휴 시 자동으로 멈추는 설정을 걸면, 오래 쉰 뒤 첫 요청은 서버가 깨어나는 동안 몇 초 기다린다(콜드 스타트). 코드는 맞고, 두 번째부터는 빠르다. "가끔 느리다"는 말을 들으면 코드보다 서버 상태부터 본다.

  • 보는 곳: 브라우저 개발자 도구의 Network 탭. 요청이 나갔나, 몇 초 걸렸나, 응답 코드가 뭐였나.
  • 서버 쪽: 서버 로그. 요청이 도착은 했나.

⑤ 배포 — 고쳤는데 그대로다

가장 많이 헷갈리는 층이다. 코드를 고치고 올렸는데 화면이 그대로면, 고친 게 틀렸다고 생각하기 쉽다. 대부분은 옛 파일이 어딘가에 남아 있는 것이다.

남아 있던 곳겪은 일과 푼 법
브라우저 캐시Cloudflare Pages 가 js·css 에 4시간 캐시를 붙인다. 고친 뒤 주소에 ?v= 숫자를 올려 새 파일로 보이게 한다
CDN 캐시파일이 없을 때 접속한 주소의 응답이 엣지에 남아, 파일을 올려도 옛 응답이 나왔다. 캐시를 비워서 풀었다
메신저 미리보기인스타·카톡은 링크 미리보기 그림을 오래 저장한다. 주소 끝에 ?s=1 같은 의미 없는 꼬리를 붙여 새 주소로 보이게 했다
스토어앱은 심사를 통과해야 사용자에게 간다. 고쳤어도 사용자 폰에는 옛 버전이 돈다
# 실제로 배포된 파일이 무엇인지 직접 받아 본다 (캐시 없이)
curl -s "https://gangmini.com/notes/gamst-scooter/?z=$RANDOM" | grep "찾는 문장"
curl -sI "https://gangmini.com/notes/note.css" | grep -i cache-control

팀에서 이게 왜 중요한가

팀에서는 층마다 담당이 다른 경우가 많다. 빌드·배포는 플랫폼 팀이, 서버는 백엔드가, 화면은 프론트엔드가 맡는다. 버그 보고에 "어느 층 같다"와 그 근거를 붙일 수 있으면, 맞는 사람에게 바로 간다. "안 돼요"만 쓰면 모두가 처음부터 다시 좁혀야 한다. 

릴리스 빌드(1.0.1)에서만 결제 화면 가격이 안 뜹니다.
- 개발 빌드: 정상   ← ① 소스는 아님
- 에뮬레이터·실기기 둘 다 같음   ← ③ 기기 문제 아님
- R8 켠 뒤부터 → ② 빌드 층, keep 규칙 확인 필요해 보입니다

위는 실제로 겪은 일이 아니라, 이 지도대로 보고하면 어떤 모양이 되는지 보인 예다. 다행히 다이어리 앱의 R8 릴리스 빌드에서는 가격이 제대로 떴다.

릴리스 빌드 — 사용자에게 나가는 빌드. 개발 빌드와 달리 코드를 줄이고 최적화한다. 그래서 개발 빌드에선 없던 문제가 생길 수 있다.
콜드 스타트 — 멈춰 있던 서버가 첫 요청을 받고 깨어나느라 늦게 응답하는 것.
CDN — 전 세계 여러 곳에 파일 사본을 두고 가까운 곳에서 내주는 망. 빠르지만, 사본이 옛것이면 옛것을 내준다.
