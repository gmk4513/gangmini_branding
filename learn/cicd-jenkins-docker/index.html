PRACTICE · CI/CD 08/13

도커로 젠킨스 띄우기
— 이미지 만들고 compose 로 실행

실습 Jenkins Docker docker compose DooD 볼륨 백업 2026.11.10

4번 글에서는 젠킨스를 우분투에 apt 로 직접 깔았다. 자바를 깔고, 저장소 키를 넣고, 서비스로 등록하고… 서버를 옮기거나 버전을 올릴 때마다 그걸 다시 해야 한다. 이번에는 젠킨스를 컨테이너로 띄운다. 설정은 파일 두 장(Dockerfile, compose 파일)에 남고, 데이터는 볼륨 하나에 모인다. 서버가 바뀌어도 파일 두 장과 볼륨만 옮기면 된다.

그리고 이 젠킨스는 9번 글에서 docker build·docker run 을 해야 한다. 7번 글에서 고른 대로 DooD(바깥 도커의 소켓 빌려 쓰기)로 간다.

이번 단계에서 할 것

  1. 도커 클라이언트를 넣은 젠킨스 이미지 만들기
  2. compose 파일 한 장으로 띄우기 (포트 8090, 볼륨, 소켓, 그룹)
  3. 초기 비밀번호로 들어가 설정 마법사 끝내기
  4. 젠킨스 안에서 docker ps 가 되는지 확인
  5. 자격 증명(dockerhub, github-token) 등록
  6. 백업과 업그레이드 방법 알아 두기

끝나면 — http://localhost:8090 에 젠킨스가 뜨고, 젠킨스 컨테이너 안에서 docker ps 를 치면 바깥 컨테이너 목록이 나온다.

무엇을 만드나

docker compose — "어떤 이미지로, 어떤 포트·볼륨·환경 변수로 띄울지"를 YAML 파일에 적어 두고 docker compose up 한 줄로 띄우는 도구. Docker Desktop 에 들어 있다.
볼륨(volume) — 컨테이너 바깥에 도커가 따로 보관하는 저장 공간. 컨테이너를 지워도 남는다. 젠킨스 데이터는 반드시 여기에 둔다.
jenkins_home — 젠킨스의 모든 것(설정, 작업, 빌드 기록, 플러그인, 자격 증명)이 들어 있는 폴더. 공식 이미지에서는 /var/jenkins_home.

0. 시작 전에

  • 2번 글대로 Docker Desktop 이 켜져 있고, 우분투 터미널에서 docker version 이 된다.
  • 4번 글의 젠킨스(8080)는 켜져 있어도 된다. 이번 것은 8090 이라 겹치지 않는다. 메모리가 빠듯하면 sudo systemctl stop jenkins 로 꺼 둔다.
mkdir -p ~/cicd/jenkins-docker
cd ~/cicd/jenkins-docker

1. 젠킨스 이미지 만들기 — 도커 CLI 넣기

공식 젠킨스 이미지(jenkins/jenkins:lts-jdk21)에는 docker 명령이 없다. 그 위에 도커 클라이언트(CLI)만 얹은 이미지를 만든다. 데몬은 넣지 않는다(DooD 니까). 

# ~/cicd/jenkins-docker/Dockerfile
FROM jenkins/jenkins:lts-jdk21

USER root
RUN apt-get update \
 && apt-get install -y --no-install-recommends ca-certificates curl \
 && install -m 0755 -d /etc/apt/keyrings \
 && curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc \
 && echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/debian $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
      > /etc/apt/sources.list.d/docker.list \
 && apt-get update \
 && apt-get install -y --no-install-recommends docker-ce-cli docker-buildx-plugin \
 && rm -rf /var/lib/apt/lists/*
USER jenkins
줄뜻
lts-jdk21LTS(오래 지원하는 안정판) 젠킨스 + 자바 21. 4번 글에서 직접 깐 것과 같은 조합
USER root프로그램을 깔려면 관리자여야 한다. 다 깔고 나서 USER jenkins 로 돌려놓는다
가운데 긴 줄도커 공식 apt 저장소를 등록한다(도커 공식 문서의 데비안 설치 방법 그대로). 젠킨스 이미지가 데비안 기반이라서
docker-ce-cli도커 클라이언트만. 데몬(docker-ce)은 안 깐다
docker-buildx-plugin요즘 docker build 가 쓰는 빌드 도구(BuildKit). 없으면 옛 빌더로 돌며 경고가 뜬다

LTS (Long-Term Support) — 새 기능은 늦게 들어오지만 오래 고쳐 주는 안정판. 젠킨스는 매주 나오는 weekly 와 12주마다 나오는 LTS 가 있다. 서버에는 LTS.
데비안(Debian) — 리눅스 배포판 하나. 우분투의 뿌리. 젠킨스 공식 이미지가 데비안 위에 만들어져 있어서 apt 로 프로그램을 깐다.

2. 소켓 그룹 번호 재기

7번 글에서 본 대로, 젠킨스 사용자(uid 1000)는 그대로는 소켓에 못 쓴다. 소켓의 그룹 번호를 재서 .env 파일에 적는다. 우분투에서 ls -l 로 보지 말고, 컨테이너 안에서 잰다. Docker Desktop 은 우분투에서 보이는 소켓과 컨테이너에 붙는 소켓의 그룹이 다르기 때문이다. 

echo "DOCKER_GID=$(docker run --rm -v /var/run/docker.sock:/var/run/docker.sock alpine stat -c %g /var/run/docker.sock)" > .env
cat .env
DOCKER_GID=0          # Docker Desktop 이면 0. 리눅스 Docker Engine 서버면 999 같은 docker 그룹 번호

.env — compose 가 자동으로 읽는 변수 파일. compose 파일 안의 ${DOCKER_GID} 자리에 이 값이 들어간다. 서버마다 다른 값을 파일 밖으로 빼는 용도.
gid (group id) — 리눅스 그룹의 번호. 권한은 이름이 아니라 번호로 따진다. 그래서 컨테이너 안과 밖의 그룹 이름이 달라도 번호만 맞으면 된다.

3. compose 파일 쓰고 띄우기

# ~/cicd/jenkins-docker/compose.yaml
services:
  jenkins:
    build: .                       # 같은 폴더의 Dockerfile 로 이미지를 만든다
    image: my-jenkins:dood         # 만든 이미지에 붙일 이름
    container_name: jenkins
    ports:
      - "8090:8080"                # 바깥 8090 → 안 8080
    volumes:
      - jenkins_home:/var/jenkins_home
      - /var/run/docker.sock:/var/run/docker.sock   # DooD: 바깥 도커 소켓 빌려 쓰기
    group_add:
      - "${DOCKER_GID}"            # 젠킨스 사용자를 소켓 그룹에 넣기
    restart: unless-stopped        # PC 를 껐다 켜도 다시 뜬다 (직접 stop 하기 전까지)

volumes:
  jenkins_home:
docker compose up -d --build
docker compose ps
NAME      IMAGE             ...   STATUS          PORTS
jenkins   my-jenkins:dood   ...   Up 20 seconds   0.0.0.0:8090->8080/tcp, 50000/tcp

처음에는 이미지를 받고 만드느라 몇 분 걸린다. STATUS 가 Up 이면 된다.

-d (detached) — 뒤에서 띄우고 터미널을 돌려준다. 빼면 로그가 화면을 차지하고, Ctrl+C 에 꺼진다.
--build — Dockerfile 이 바뀌었으면 이미지를 새로 만들고 띄운다.
50000/tcp — 젠킨스가 다른 컴퓨터(에이전트)와 이야기하는 포트. 이번엔 안 쓰니 바깥에 열지 않았다.

4. 초기 비밀번호로 들어가기

젠킨스는 처음 뜰 때 관리자 비밀번호를 하나 만들어 로그와 파일에 남긴다. 둘 중 편한 쪽으로 본다.

docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword
# 또는
docker compose logs jenkins | grep -A 2 "following password"
jenkins  | [LF]> Please use the following password to proceed to installation:
jenkins  | [LF]>
jenkins  | [LF]> 3f1c0e…(32자리 영숫자)

로그 쪽에 붙는 [LF]> 는 젠킨스가 여러 줄짜리 메시지를 표시하는 방식이라 신경 쓰지 않는다. 비밀번호는 맨 아래 32자리만 복사한다.

  1. 브라우저(윈도우)에서 http://localhost:8090 을 연다.
  2. Unlock Jenkins 칸에 위 비밀번호를 붙여 넣는다.
  3. Install suggested plugins 를 누른다. Git, Pipeline, Credentials Binding, Timestamper 같은 기본 플러그인이 깔린다(몇 분).
  4. 관리자 계정을 만든다. 4번 글의 젠킨스와는 완전히 따로라 다시 만든다.
  5. Jenkins URL 은 http://localhost:8090/ 그대로 두고 저장.

Docker Pipeline 플러그인 (선택)

9번 글의 파이프라인은 sh 'docker build …' 처럼 셸 명령으로 도커를 부르므로 추가 플러그인이 없어도 된다. 그래도 Manage Jenkins → Plugins → Available plugins 에서 Docker Pipeline 을 깔아 두면 Jenkinsfile 에서 docker.build(…), agent { docker { image 'python:3.12' } } 같은 문법을 쓸 수 있다. 단계 그림이 안 보이면 같은 곳에서 Pipeline Stage View(또는 Pipeline Graph View)를 깐다.

플러그인(plugin) — 젠킨스에 기능을 더하는 확장. 젠킨스 본체는 작고, Git 연동·파이프라인 문법·도커 연동이 전부 플러그인이다. 플러그인도 jenkins_home 에 깔린다.

5. 젠킨스 안에서 도커가 되는지 확인

docker exec jenkins id
docker exec jenkins docker ps --format 'table {{.Names}}\t{{.Image}}'
uid=1000(jenkins) gid=1000(jenkins) groups=1000(jenkins),0(root)
NAMES     IMAGE
jenkins   my-jenkins:dood

groups 에 소켓 그룹(여기선 0)이 붙어 있고, docker ps 에 젠킨스 자기 자신이 보인다. 바깥 데몬을 빌려 쓰고 있다는 뜻이다. (이 글의 Dockerfile·compose 파일 그대로 Docker Desktop 29.6.1 에서 띄워 위 두 줄과 초기 비밀번호, 백업 명령까지 확인했다. 그때 이미지 안의 자바는 21.0.13, 도커 CLI 는 29.9.3 이었다.)

화면에서도 확인할 수 있다. New Item → 이름 docker-check → Pipeline, 아래 Script 칸에 이걸 넣고 Build Now. 

pipeline {
  agent any
  stages {
    stage('docker') {
      steps {
        sh 'docker version'
        sh 'docker ps'
      }
    }
  }
}

Console Output 에 Client 와 Server 버전이 둘 다 나오고 Finished: SUCCESS 면 된다. Server 쪽이 permission denied 면 2번(.env) 으로 돌아간다.

6. 자격 증명 등록 — dockerhub, github-token

9번 글에서 이미지를 Docker Hub 에 올리려면 로그인 정보가 필요하다. 파이프라인 파일에 쓰지 않고 젠킨스에 맡긴다.

Docker Hub 액세스 토큰 만들기

  1. hub.docker.com 로그인 → 오른쪽 위 프로필 → Account settings → Personal access tokens → Generate new token
  2. 이름 jenkins, 권한 Read & Write → 만들기. 토큰은 이 화면에서만 보이니 바로 복사한다.

액세스 토큰(access token) — 비밀번호 대신 쓰는 열쇠. 권한을 좁힐 수 있고, 새면 그것만 지우면 된다. 계정 비밀번호를 젠킨스에 넣지 않는다.

젠킨스에 넣기

  1. Manage Jenkins → Credentials → System → Global credentials (unrestricted) → Add Credentials
  2. Kind: Username with password
  3. Username: 도커허브 아이디, Password: 방금 복사한 토큰
  4. ID: dockerhub (9번 Jenkinsfile 이 이 이름으로 찾는다. 철자 그대로)
  5. 같은 방법으로 ID github-token: Username 은 GitHub 아이디, Password 는 3번 글에서 만든 GitHub 토큰(PAT). 공개 저장소를 읽기만 할 땐 없어도 되지만, 13번 글에서 젠킨스가 매니페스트 저장소에 push 할 때 필요하다.

저장한 뒤 목록에는 dockerhub 와 아이디만 보이고 비밀번호는 다시 볼 수 없다. 이 값도 jenkins_home 안에 암호화되어 저장된다.

7. 백업과 복원 — 볼륨을 tar 로

젠킨스의 모든 것은 볼륨 하나에 있으니 백업도 그것 하나다. 볼륨 이름은 폴더이름_볼륨이름 이 된다. 

docker volume ls | grep jenkins_home
local     jenkins-docker_jenkins_home
# 백업: 볼륨을 잠깐 다른 컨테이너에 붙여 압축한다 (일관성을 위해 젠킨스는 잠시 멈춤)
docker compose stop
docker run --rm \
  -v jenkins-docker_jenkins_home:/data:ro \
  -v "$PWD":/backup \
  alpine tar czf /backup/jenkins_home-$(date +%F).tgz -C /data .
docker compose start
ls -lh jenkins_home-*.tgz
# 복원: 빈 볼륨에 풀기 (새 서버라면 compose 파일과 이 tgz 만 옮기면 된다)
docker compose down
docker volume create jenkins-docker_jenkins_home
docker run --rm \
  -v jenkins-docker_jenkins_home:/data \
  -v "$PWD":/backup \
  alpine sh -c "cd /data && tar xzf /backup/jenkins_home-2026-11-10.tgz"
docker compose up -d

여기서 -v "$PWD":/backup 는 우분투 터미널에서 친 명령이라 문제없다. 7번 글의 함정은 컨테이너 안에서 -v 를 쓸 때다.

8. 업그레이드 — 이미지만 새로

docker compose build --pull      # 새 lts-jdk21 을 받아 이미지 다시 만들기
docker compose up -d             # 바뀐 이미지로 컨테이너만 갈아 끼우기
docker exec jenkins java -jar /usr/share/jenkins/jenkins.war --version
2.580.2        # 2026-11-10 에 받은 lts-jdk21 기준. 받는 날에 따라 다르다

컨테이너는 새것이 되지만 볼륨은 그대로라 작업·기록·플러그인이 남는다. 올리기 전에 위 백업을 먼저 한다. 플러그인 업데이트는 젠킨스 화면의 Manage Jenkins → Plugins → Updates 에서 따로 한다.

9. 한 걸음 더 — 플러그인까지 이미지에 굽기

화면에서 플러그인을 고르면, 서버를 새로 만들 때 또 골라야 한다. 플러그인 목록을 파일로 두고 이미지 만들 때 같이 깔 수 있다. 

# plugins.txt
workflow-aggregator
git
docker-workflow
credentials-binding
timestamper
pipeline-stage-view
# Dockerfile 맨 아래 USER jenkins 다음에 추가
COPY --chown=jenkins:jenkins plugins.txt /usr/share/jenkins/ref/plugins.txt
RUN jenkins-plugin-cli -f /usr/share/jenkins/ref/plugins.txt

jenkins-plugin-cli 는 공식 이미지에 들어 있는 플러그인 설치 도구다. 이름은 화면 이름이 아니라 플러그인 ID(docker-workflow = Docker Pipeline)다. 더 나아가면 설정 마법사와 화면 설정까지 YAML 로 적는 JCasC(Configuration as Code 플러그인)가 있다. 이번 실습은 화면으로 충분하다.

JCasC (Jenkins Configuration as Code) — 젠킨스 설정(보안, 자격 증명 자리, 에이전트 등)을 YAML 파일로 적어 두고 시작할 때 읽게 하는 플러그인. 서버를 여러 대 같은 모양으로 만들 때 쓴다. 11번 글에서 헬름으로 깔 젠킨스가 이 방식을 쓴다.

이 글의 용어 정리
compose 파일 — 컨테이너 띄우는 방법을 적은 YAML. up -d 로 띄우고 down 으로 내린다.
볼륨 — 컨테이너가 사라져도 남는 저장 공간. 젠킨스 데이터의 집.
group_add — 컨테이너 사용자를 추가 그룹에 넣는 설정. 소켓 권한을 이걸로 푼다.
restart: unless-stopped — 꺼지면 다시 켜되, 내가 직접 멈춘 건 그대로 둔다.
자격 증명(credentials) — 젠킨스가 대신 보관하는 아이디·토큰. 파이프라인에서는 ID 로만 부른다.
