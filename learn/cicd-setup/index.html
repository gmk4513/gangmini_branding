1편에서 그린 지도대로 가려면 리눅스 서버, 도커, 쿠버네티스가 필요하다. 회사라면 진짜 서버가 있겠지만, 실습은 내 윈도우 컴퓨터 안에 리눅스(우분투)를 하나 띄워서 그걸 "회사 서버"로 삼는다. 그게 WSL2 다. 이 글은 시리즈를 시작하기 전에 한 번만 해 두는 준비다. 설치가 대부분이라 다운로드 시간을 포함해 1시간쯤 잡는다.

이번 단계에서 할 것

  • WSL2 로 우분투 24.04 설치, systemd 켜져 있는지 확인
  • Docker Desktop 설치하고 우분투에서 docker 명령이 되게 연결
  • kubectl · kind · helm · git · gh 설치
  • GitHub · Docker Hub 계정 준비, Docker Hub 토큰 만들기
  • 실습 폴더 ~/cicd 만들기

끝나면: 우분투 터미널에서 docker run hello-world, kubectl version --client, kind version, helm version 이 모두 답을 한다.

한눈에 — 무엇이 어디서 도나

WSL2 (Windows Subsystem for Linux 2) — 윈도우 안에서 진짜 리눅스를 돌리는 기능. 마이크로소프트가 만든 가벼운 가상 머신 위에 우분투 같은 리눅스를 올린다. 따로 VM 프로그램을 깔 필요가 없다.
우분투(Ubuntu) — 가장 널리 쓰는 리눅스 배포판 중 하나. 회사 서버에도 많이 쓴다. 24.04 는 2024년 4월에 나온 장기 지원(LTS) 버전이라는 뜻.
Docker Desktop — 윈도우·맥에서 도커를 쓰게 해 주는 프로그램. 도커 엔진을 WSL2 안에 띄우고, 우분투에서 그 엔진을 부를 수 있게 이어 준다.

시리즈 후반에는 쿠버네티스 + 젠킨스 + ArgoCD 가 한꺼번에 뜬다. 메모리를 꽤 쓴다.

1. WSL2 와 우분투 24.04 설치

시작 메뉴에서 PowerShell 을 관리자 권한으로 실행하고 친다. (이 단계만 윈도우 PowerShell 이고, 다음부터는 전부 우분투다.)

wsl --install -d Ubuntu-24.04
  1. 처음이면 WSL 기능을 켜고 재부팅하라고 한다. 재부팅한다.
  2. 재부팅 후 우분투 창이 저절로 열리며 리눅스용 사용자 이름과 비밀번호를 묻는다. 윈도우 계정과 상관없다. 영어 소문자로 짧게(예: me). 비밀번호는 쳐도 화면에 안 보이는 게 정상이다.
  3. 이 비밀번호는 sudo 를 칠 때마다 쓴다. 잊지 않게 적어 둔다.

PowerShell 에서 버전 2 인지 확인한다.

wsl -l -v
  NAME            STATE           VERSION
* Ubuntu-24.04    Running         2

VERSION 이 1 이면 wsl --set-version Ubuntu-24.04 2 로 바꾼다. 이미 다른 우분투(예: 22.04)가 깔려 있다면 그걸 써도 된다. 우분투 안에서 lsb_release -a 로 버전을 보고 22.04 이상이면 된다.

앞으로 우분투 터미널은 시작 메뉴의 Ubuntu 24.04 를 누르거나, 윈도우 터미널(Windows Terminal)의 탭 목록에서 연다. 프롬프트가 me@PC이름:~$ 처럼 생겼으면 우분투다. 이 시리즈의 모든 명령은 여기에 친다.

먼저 패키지 목록을 최신으로 맞춰 둔다.

sudo apt update && sudo apt upgrade -y

sudo — "관리자 권한으로 실행". 시스템 파일을 바꾸거나 프로그램을 설치할 때 앞에 붙인다. 처음 한 번 비밀번호를 묻는다.
apt — 우분투의 프로그램 설치 도구. apt update 는 "설치 가능한 목록 새로 받기", apt install 이름 은 설치. 앱스토어를 명령으로 쓰는 셈이다.
LTS (Long Term Support) — 오래(우분투는 5년) 보안 업데이트를 해 주는 버전. 서버에는 보통 LTS 를 쓴다.

2. systemd 가 켜져 있나

4편에서 젠킨스를, 5편에서 실습 앱을 systemd 서비스로 띄운다. 회사 리눅스 서버에서 프로그램을 "항상 켜져 있게" 관리하는 표준 방법이다. WSL 은 예전엔 systemd 가 꺼져 있었다. 새로 깐 우분투 24.04 는 기본으로 켜져 있지만 확인한다. 

ps -p 1 -o comm=
systemd

systemd 가 나오면 끝. init 같은 다른 이름이 나오면 설정 파일을 연다.

sudo nano /etc/wsl.conf
[boot]
systemd=true

저장(Ctrl+O, 엔터)하고 나와서(Ctrl+X), 윈도우 PowerShell 에서 wsl --shutdown 을 친 뒤 우분투를 다시 연다. 다시 ps -p 1 -o comm= 으로 확인한다.

systemd — 리눅스가 켜질 때 가장 먼저 시작해서(프로세스 번호 1번) 나머지 프로그램들을 켜고 끄고 지켜보는 관리자. "이 프로그램을 부팅할 때 켜 둬, 죽으면 다시 살려"를 맡긴다. 명령은 systemctl.
서비스(service) — systemd 가 관리하는 상시 실행 프로그램. sudo systemctl status jenkins 처럼 이름으로 다룬다.

3. WSL 이 쓸 메모리 정하기 (선택이지만 권장)

WSL2 는 기본으로 컴퓨터 메모리의 절반까지 쓴다. Docker Desktop 도 같은 WSL2 안에서 돌기 때문에 이 한도를 같이 쓴다. 16GB 컴퓨터라면 8GB 정도로 정해 두면 윈도우가 느려지지 않는다. 윈도우 탐색기 주소창에 %UserProfile% 를 치고, 그 폴더에 .wslconfig 파일을 만든다(메모장으로 만들 때 확장자 .txt 가 붙지 않게 주의). 

# C:\Users\윈도우사용자\.wslconfig
[wsl2]
memory=8GB
processors=4
swap=4GB

PowerShell 에서 wsl --shutdown 후 우분투를 다시 열면 적용된다. 우분투에서 free -h 의 total 이 8GB 가까이 나오면 된다.

4. Docker Desktop 설치와 우분투 연결

  1. docker.com 에서 Docker Desktop for Windows 를 받아 설치한다. 설치 화면의 Use WSL 2 instead of Hyper-V 는 켠 채로 둔다.
  2. 설치 후 Docker Desktop 을 실행한다. 왼쪽 아래가 초록(Engine running)이 될 때까지 기다린다.
  3. 오른쪽 위 톱니바퀴 Settings → Resources → WSL integration 에서 Ubuntu-24.04 스위치를 켜고 Apply & restart.

이제 우분투 터미널에서(새로 열어서) 확인한다.

docker version
docker run hello-world

대략 이렇게 나오면 성공이다(버전 숫자는 다르다).

Client:
 Version:           29.x.x
 ...
Server: Docker Desktop
 Engine:
  Version:          29.x.x
...
Hello from Docker!
This message shows that your installation appears to be working correctly.
  • 우분투 안에 apt install docker.io 로 도커를 또 깔지 않는다. Docker Desktop 의 도커와 엔진이 두 개가 되어 서로 꼬인다.
  • 실습 내내 Docker Desktop 은 켜 둔다. 꺼지면 우분투의 docker 명령이 "Cannot connect to the Docker daemon" 에러를 낸다.
  • Docker Desktop 은 개인·교육·작은 회사(직원 250명 미만이고 매출 1천만 달러 미만)는 무료다. 큰 회사는 유료 구독이 필요하다.

도커 엔진(Docker Engine, 데몬) — 이미지를 받고 컨테이너를 실제로 띄우는 뒤편의 프로그램. 우리가 치는 docker 명령(클라이언트)은 엔진에게 "이거 해 줘"라고 부탁만 한다. 둘이 따로라는 점이 7편 DooD 의 핵심이다.
hello-world — 도커가 제공하는 시험용 이미지. 받아서 실행되면 메시지 몇 줄을 찍고 끝난다. 받기 → 컨테이너 만들기 → 실행이 다 되는지 보는 용도.

3편에서 파이썬 테스트를 돌리고, 여러 편에서 curl 로 주소를 불러 볼 것이다.

sudo apt install -y git curl ca-certificates unzip python3 python3-venv python3-pip
git --version
python3 --version
git version 2.43.0
Python 3.12.3

(우분투 24.04 컨테이너에서 같은 명령으로 설치했을 때 나온 버전이다. 업데이트에 따라 끝자리는 다를 수 있다.)

6. kubectl — 쿠버네티스에 말 거는 명령

공식 문서의 방법 그대로, 최신 안정판 파일을 받아 /usr/local/bin 에 넣는다.

cd ~
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl
rm kubectl
kubectl version --client
Client Version: v1.37.2
Kustomize Version: v5.8.1

(2026-11-10 에 같은 주소로 받은 파일을 리눅스 컨테이너에서 실행해 나온 출력이다. 받는 날에 따라 숫자가 다르다.) 아직 연결할 클러스터가 없으니 kubectl get nodes 를 치면 에러가 나는 게 정상이다. 클러스터는 10편에서 만든다.

kubectl — "큐브컨트롤" 또는 "큐브씨티엘"로 읽는다. 쿠버네티스 클러스터에 "이 앱을 띄워", "지금 뭐가 떠 있어?"를 묻는 명령줄 도구.
/usr/local/bin — 내가 직접 넣은 실행 파일을 두는 폴더. 여기 넣으면 어느 폴더에서든 이름만으로 실행된다(PATH 에 들어 있어서).
클러스터(cluster) — 쿠버네티스가 하나로 묶어 관리하는 서버(노드)들의 무리.

7. kind — 도커 안에 쿠버네티스 띄우는 도구

진짜 쿠버네티스는 서버가 여러 대 필요하다. kind 는 도커 컨테이너 하나를 서버 한 대처럼 써서, 내 컴퓨터에 연습용 클러스터를 1분 만에 만든다.

[ $(uname -m) = x86_64 ] && curl -Lo ./kind https://kind.sigs.k8s.io/dl/v0.33.0/kind-linux-amd64
chmod +x ./kind
sudo mv ./kind /usr/local/bin/kind
kind version
kind v0.33.0 go1.26.7 linux/amd64

주소의 v0.33.0 은 2026-11-10 기준 최신판이다. 새 버전이 나왔으면 kind 설치 문서의 줄을 그대로 복사해 쓴다. 클러스터 만들기(kind create cluster)는 10편에서 한다. 지금 만들어 두면 메모리만 먹는다.

kind (Kubernetes IN Docker) — 쿠버네티스 노드를 도커 컨테이너로 흉내 내는 도구. 쿠버네티스 개발자들이 테스트용으로 만들었다. 연습·CI 용이지 운영용이 아니다. 비슷한 도구로 minikube, k3d 가 있다.

8. helm — 쿠버네티스 앱 설치 도구

11편에서 젠킨스를 쿠버네티스 안에 설치할 때 쓴다. 공식 설치 스크립트를 받아 실행한다.

curl -fsSL -o get_helm.sh https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-4
chmod 700 get_helm.sh
./get_helm.sh
rm get_helm.sh
helm version
helm installed into /usr/local/bin/helm
version.BuildInfo{Version:"v4.3.1", GitCommit:"c0d08d0...", GitTreeState:"clean", GoVersion:"go1.27.2", KubeClientVersion:"v1.37"}

2026-11-10 기준 최신은 Helm 4(v4.3.1)다. 11편에서 쓰는 helm repo add · helm install 은 Helm 3 와 같은 모양이라, 이미 Helm 3 가 깔려 있으면 그대로 써도 된다. 스크립트 주소가 바뀌었으면 Helm 설치 문서를 본다.

Helm — 쿠버네티스용 패키지 관리자. 젠킨스처럼 YAML 파일 수십 개로 이뤄진 프로그램을 차트(chart)라는 묶음으로 받아 한 줄로 설치·업그레이드·삭제한다. 우분투의 apt 가 하는 일을 쿠버네티스에서 한다.

9. Git 과 GitHub CLI

Git 에 내 이름을 알려 준다. 커밋마다 찍힌다.

git config --global user.name "내이름"
git config --global user.email "GitHub에 등록한 이메일"
git config --global init.defaultBranch main

공개 저장소에 진짜 이메일을 남기기 싫으면 GitHub → Settings → Emails 의 …@users.noreply.github.com 주소를 쓴다. 그다음 GitHub 를 명령으로 다루는 gh 를 깐다(공식 설치 문서의 우분투 방법). 

(type -p wget >/dev/null || (sudo apt update && sudo apt install wget -y)) \
  && sudo mkdir -p -m 755 /etc/apt/keyrings \
  && out=$(mktemp) && wget -nv -O$out https://cli.github.com/packages/githubcli-archive-keyring.gpg \
  && cat $out | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null \
  && sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg \
  && sudo mkdir -p -m 755 /etc/apt/sources.list.d \
  && echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null \
  && sudo apt update \
  && sudo apt install gh -y

로그인한다. 질문에는 이렇게 고른다.

gh auth login
질문고를 것
Where do you use GitHub?GitHub.com
Preferred protocol for Git operations?HTTPS
Authenticate Git with your GitHub credentials?Yes — 이후 git push 가 비밀번호를 안 묻는다
How would you like to authenticate?Login with a web browser

화면에 8자리 코드가 나온다. WSL 에서는 브라우저가 저절로 안 열릴 수 있다. 그러면 윈도우 브라우저에서 https://github.com/login/device 를 직접 열고 코드를 넣는다. gh auth status 에 Logged in to github.com 이 나오면 끝.

GitHub CLI (gh) — 저장소 만들기, PR 열기 같은 GitHub 웹 화면의 일을 터미널에서 하는 도구. 없어도 웹에서 같은 걸 할 수 있다.
HTTPS / SSH — Git 이 GitHub 와 통신하는 두 방법. HTTPS 는 주소가 https://github.com/... 이고 토큰으로 인증, SSH 는 git@github.com:... 이고 열쇠 파일로 인증. 이 시리즈는 HTTPS 로 통일한다(젠킨스도 HTTPS + 토큰을 쓴다).

10. 계정 두 개 — GitHub 와 Docker Hub

GitHub

없으면 github.com 에서 만든다. 시리즈에서 공개 저장소 두 개(cicd-hello, cicd-hello-manifests)를 만든다. 젠킨스가 쓸 토큰(PAT)은 3편에서 저장소를 만든 뒤에 만든다. 토큰 권한을 그 저장소에만 주기 위해서다.

Docker Hub

  1. hub.docker.com 에서 무료 계정을 만든다. 아이디(Docker ID)가 이미지 이름 앞에 붙는다: <도커허브아이디>/cicd-hello. 이 글들에서 <도커허브아이디> 라고 쓴 자리에 이 아이디를 넣는다.
  2. 오른쪽 위 프로필 → Account settings → Personal access tokens → Generate new token.
  3. Description 은 jenkins-cicd, Access permissions 는 Read & Write(이미지를 올려야 하니까). 만료일은 실습 기간에 맞게.
  4. Generate 를 누르면 토큰이 딱 한 번 보인다. 비밀번호 관리자나 안전한 메모에 적어 둔다. 9편·11편에서 젠킨스에 넣는다.

우분투에서 토큰으로 로그인되는지 확인한다. 비밀번호 자리에 토큰을 붙여 넣는다.

docker login -u <도커허브아이디>
Password:              ← 토큰 붙여 넣기 (화면엔 안 보인다)
Login Succeeded

액세스 토큰(Access Token) — 비밀번호 대신 쓰는 긴 문자열. 권한(읽기만/쓰기도)과 만료일을 정할 수 있고, 새어 나가면 그 토큰만 지우면 된다. 그래서 프로그램(젠킨스)에는 진짜 비밀번호가 아니라 토큰을 준다.
Docker Hub — 도커가 운영하는 공개 이미지 보관소(레지스트리). python:3.12-slim 같은 공식 이미지도 여기서 받는다. 무료 계정은 공개 저장소를 만들 수 있고, 받기(pull) 횟수에 한도가 있다.

11. 실습 폴더

mkdir -p ~/cicd
cd ~/cicd
pwd
/home/me/cicd
  • 실습 파일은 우분투 홈(~) 안에 둔다. 윈도우 폴더(/mnt/c/...)에서도 열리긴 하지만, 리눅스↔윈도우를 건너다니느라 아주 느리고 파일 권한·줄바꿈 문제가 생긴다.
  • 코드는 VS Code 로 고치면 편하다. 윈도우에 VS Code 와 WSL 확장(Microsoft)을 깔아 두면, 우분투 폴더 안에서 code . 을 쳤을 때 VS Code 가 그 폴더를 열고 아래 터미널도 우분투가 된다.
  • 윈도우 탐색기에서 우분투 파일을 보고 싶으면 주소창에 \\wsl$\Ubuntu-24.04\home\me\cicd.

용어 정리

WSL2 — 윈도우 안의 진짜 리눅스. 이 시리즈에서 "회사 서버" 역할.
systemd · 서비스 — 리눅스에서 프로그램을 항상 켜 두고 관리하는 장치와 그 단위. 4·5편에서 쓴다.
도커 엔진 / 클라이언트 — 컨테이너를 실제로 돌리는 쪽 / 명령을 보내는 쪽. 둘은 따로다.
kubectl — 쿠버네티스에 명령하는 도구. kind — 도커 안에 연습용 쿠버네티스를 만드는 도구. helm — 쿠버네티스용 설치 도구.
gh — GitHub 를 터미널에서 다루는 도구.
액세스 토큰 — 프로그램에 주는, 권한과 만료일이 있는 비밀번호 대용.
