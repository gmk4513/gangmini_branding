PRACTICE · CI/CD 12/13

ArgoCD 설치와 사용법
— GitOps 첫걸음

실습 ArgoCD GitOps Kubernetes Sync 드리프트 2026.11.10

10편에서 YAML 을 고치고 kubectl apply 를 손으로 쳤다. 그리고 두 번 "파일과 클러스터가 어긋났다"를 봤다(kubectl scale, rollout undo). 사람이 여럿이면 이런 어긋남은 매일 생긴다. 누가 언제 무엇을 바꿨는지도 남지 않는다.

GitOps 는 규칙을 하나 정한다. "클러스터에 있어야 할 것은 전부 Git 에 적혀 있고, 클러스터는 Git 과 똑같아야 한다." 바꾸고 싶으면 Git 에 커밋한다. 그러면 클러스터 안의 프로그램이 Git 을 보고 알아서 맞춘다. 그 프로그램이 ArgoCD 다.

이번 단계에서 할 것

  1. ArgoCD 를 10편의 kind 클러스터에 설치하고 화면·CLI 로 로그인하기
  2. 매니페스트만 담는 Git 저장소 cicd-hello-manifests 만들기
  3. ArgoCD Application 을 만들어 cicd-hello 배포하기
  4. Git 으로 바꾸기, 손으로 바꿨을 때(드리프트) 잡아내기, 자동 동기화 켜기, 되돌리기

끝나면: ArgoCD 화면에서 cicd-hello 가 Synced · Healthy 이고, kubectl 로 몰래 바꾼 것이 몇 초 만에 Git 대로 돌아간다.

push 방식과 pull 방식

GitOps — Git 저장소를 "운영 환경의 정답지(단일 진실 공급원)"로 삼는 운영 방식. 바꾸는 방법은 커밋 하나뿐이고, 되돌리기는 git revert 다.
단일 진실 공급원(Single Source of Truth) — "정답은 여기 하나에만 있다"는 원칙. 클러스터, 누군가의 노트북, 위키에 서로 다른 설정이 흩어지지 않게 한다.
ArgoCD — 쿠버네티스 안에서 도는 GitOps 도구. Git 의 매니페스트와 클러스터의 실제 상태를 계속 비교하고, 다르면 알려 주거나 맞춘다. CNCF(쿠버네티스를 관리하는 재단)의 졸업(graduated) 프로젝트다.
CD 도구와 CI 도구의 분리 — 젠킨스는 테스트하고 이미지를 만드는 데까지(CI), 배포는 ArgoCD 가(CD). 13편에서 둘을 잇는다.

1. ArgoCD 설치

10편의 클러스터인지 먼저 확인하고(kubectl config current-context → kind-cicd), 공식 설치 파일을 그대로 적용한다.

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts \
  -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

--server-side 는 ArgoCD 의 CRD 가 커서 붙인다. 이게 없으면 버전에 따라 metadata.annotations: Too long 에러가 난다. 설치 줄은 바뀔 수 있으니 안 되면 공식 Getting Started 의 최신 줄을 쓴다. 

kubectl -n argocd wait --for=condition=Ready pods --all --timeout=300s
kubectl -n argocd get pods
NAME                                                READY   STATUS
argocd-application-controller-0                     1/1     Running
argocd-applicationset-controller-xxxxx              1/1     Running
argocd-dex-server-xxxxx                             1/1     Running
argocd-notifications-controller-xxxxx               1/1     Running
argocd-redis-xxxxx                                  1/1     Running
argocd-repo-server-xxxxx                            1/1     Running
argocd-server-xxxxx                                 1/1     Running
구성 요소하는 일
argocd-server웹 화면과 API. 우리가 접속하는 곳
argocd-repo-serverGit 저장소를 받아 매니페스트(YAML)를 만들어 낸다
argocd-application-controllerGit 의 매니페스트와 클러스터 실제 상태를 계속 비교하고, 동기화한다. ArgoCD 의 심장
argocd-redis계산 결과를 잠깐 담아 두는 캐시
dex-server, notifications, applicationset사내 로그인 연동, 슬랙 알림 등, 앱 여러 개 찍어 내기. 이 실습에서는 안 쓴다

CRD(Custom Resource Definition) — 쿠버네티스에 새 오브젝트 종류를 더하는 방법. ArgoCD 를 깔면 Application 이라는 종류가 생겨서, Deployment 처럼 YAML 로 만들 수 있다.
server-side apply — 합치는 계산을 kubectl 이 아니라 API 서버가 하게 하는 apply 방식. 마지막 적용 내용을 거대한 주석(annotation)에 적어 두지 않아서 큰 CRD 도 들어간다.

2. 화면에 로그인

kubectl -n argocd port-forward svc/argocd-server 8443:443

열어 둔 채로 브라우저에서 https://localhost:8443. "연결이 비공개로 설정되어 있지 않습니다" 경고가 나온다. ArgoCD 가 스스로 만든 인증서라 그렇다. 고급 → localhost(안전하지 않음)로 이동. 연습용 로컬 주소라서 괜찮다. 아이디는 admin, 첫 비밀번호는 새 터미널에서: 

kubectl -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath="{.data.password}" | base64 -d; echo

자체 서명 인증서(self-signed certificate) — 공인 기관이 아니라 프로그램이 스스로 발급한 HTTPS 인증서. 암호화는 되지만 "누구인지"를 보증하지 못해 브라우저가 경고한다. 실서버에서는 도메인을 붙이고 정식 인증서를 쓴다.

3. CLI 설치와 비밀번호 바꾸기

화면으로 다 할 수 있지만 CLI 가 있으면 13편에서 상태를 빠르게 본다.

curl -sSL -o argocd https://github.com/argoproj/argo-cd/releases/latest/download/argocd-linux-amd64
sudo install -m 555 argocd /usr/local/bin/argocd
rm argocd
argocd version --client

argocd login localhost:8443 --username admin --password '<위 비밀번호>' --insecure
argocd account update-password

--insecure 는 2번의 인증서 경고를 CLI 에서 넘기는 옵션이다. 비밀번호를 바꿨으면 첫 비밀번호 Secret 은 지워도 된다(공식 문서도 권한다): kubectl -n argocd delete secret argocd-initial-admin-secret

4. 매니페스트 저장소 만들기

앱 코드 저장소(cicd-hello)와 따로 배포용 YAML 만 담는 저장소를 만든다. 왜 따로인지는 13편에서 자세히 보고, 지금은 짧게: 앱 코드의 커밋 기록과 "운영에 무엇이 언제 나갔나" 기록이 섞이지 않고, 권한도 따로 줄 수 있다. 

mkdir -p ~/cicd/cicd-hello-manifests/k8s
cd ~/cicd/cicd-hello-manifests
cp ~/cicd/k8s-practice/k8s/deployment.yaml ~/cicd/k8s-practice/k8s/service.yaml k8s/

k8s/deployment.yaml 의 image: 를 11편에서 올린 태그로 맞춘다(예: <도커허브아이디>/cicd-hello:1-a1b2c3d). namespace.yaml 은 가져오지 않는다. 네임스페이스는 ArgoCD 가 만들게 한다(5번의 CreateNamespace=true). 

printf '# cicd-hello-manifests\n\ncicd-hello 의 쿠버네티스 배포 설정. ArgoCD 가 이 저장소의 k8s/ 를 보고 배포한다.\n' > README.md
git init -b main
git add .
git commit -m "cicd-hello 배포 매니페스트"
gh repo create cicd-hello-manifests --public --source . --push

공개 저장소라 ArgoCD 가 따로 로그인하지 않고 읽는다. 비공개로 하려면 아래 "비공개 저장소라면" 을 본다. 이 저장소의 main 에는 3편처럼 "PR 필수" 규칙을 걸지 않는다. 13편에서 젠킨스가 여기에 바로 push 하기 때문이다.

5. Application 만들기

ArgoCD 에서 배포 단위 하나를 Application 이라고 한다. "이 Git 저장소의 이 폴더를 → 이 클러스터의 이 네임스페이스에" 라는 연결 하나다. 화면에서 + NEW APP 으로 칸을 채워도 되지만, 이것도 YAML 로 쓰면 기록이 남는다. 이 파일은 매니페스트 저장소의 k8s/ 밖에 둔다(k8s/ 안에 두면 ArgoCD 가 자기 설정까지 배포하려 든다). 

mkdir -p ~/cicd/cicd-hello-manifests/argocd
# argocd/application.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: cicd-hello
  namespace: argocd
  finalizers:
    - resources-finalizer.argocd.argoproj.io
spec:
  project: default
  source:
    repoURL: https://github.com/<내아이디>/cicd-hello-manifests.git
    targetRevision: main
    path: k8s
  destination:
    server: https://kubernetes.default.svc
    namespace: cicd-hello
  syncPolicy:
    syncOptions:
      - CreateNamespace=true
줄뜻
metadata.namespace: argocdApplication 오브젝트 자체는 argocd 네임스페이스에 둔다. 앱이 배포될 곳(destination)과 다르다
finalizers이 Application 을 지우면 배포했던 Deployment·Service 도 같이 지운다. 없으면 Application 만 사라지고 앱은 남는다
project: default권한 묶음. 팀이 여럿이면 프로젝트별로 "어느 저장소에서, 어느 네임스페이스로" 를 제한한다
source정답지 위치: 저장소, 브랜치(targetRevision), 폴더(path)
destination.serverhttps://kubernetes.default.svc = "ArgoCD 가 깔린 바로 이 클러스터". 다른 클러스터도 등록해서 배포할 수 있다
syncPolicy지금은 자동 동기화 없음(손으로 Sync). 8번에서 켠다
kubectl apply -f argocd/application.yaml
git add argocd && git commit -m "ArgoCD Application 정의" && git push

화면에 cicd-hello 카드가 생긴다. 상태는 OutOfSync · Missing. "Git 에는 있는데 클러스터엔 아직 없다"는 뜻이다. 카드를 열고 SYNC → SYNCHRONIZE. 몇 초 뒤 Synced · Healthy 가 되고, Application → Deployment → ReplicaSet → Pod 두 개, Service 로 이어지는 나무 그림이 그려진다. 

argocd app get cicd-hello

대략 이런 모양이 나온다(버전에 따라 줄이 더 있다).

Name:               argocd/cicd-hello
Sync Status:        Synced to main (3f2a9c1)
Health Status:      Healthy

KIND        NAMESPACE   NAME        STATUS  HEALTH
Service     cicd-hello  cicd-hello  Synced  Healthy
Deployment  cicd-hello  cicd-hello  Synced  Healthy
kubectl -n cicd-hello port-forward svc/cicd-hello 8200:80     # 다른 터미널에서 curl localhost:8200/

두 가지 상태를 따로 읽는다

Sync 상태 — Git 과 같은가Health 상태 — 잘 돌고 있나
Synced Git 과 똑같다Healthy 파드가 다 준비됨
OutOfSync Git 과 다르다 (Git 이 바뀌었거나 누가 클러스터를 바꿨다)Progressing 배포 중, 파드 뜨는 중
Unknown 비교 자체를 못 함 (저장소 주소 오류 등)Degraded 실패. 대개 ImagePullBackOff·CrashLoopBackOff
Missing 아직 클러스터에 없음

둘은 따로 논다. Synced 인데 Degraded 일 수 있다 — "Git 대로 정확히 배포했는데, Git 에 적힌 이미지 태그가 틀렸다" 같은 경우다.

Sync(동기화) — Git 의 매니페스트를 클러스터에 적용해 둘을 같게 만드는 일. 속으로는 kubectl apply 와 비슷한 일을 한다.
Refresh — Git 을 지금 다시 읽어 비교만 하는 것(적용은 안 함). ArgoCD 는 기본으로 약 3분마다 저장소를 다시 읽는다. 기다리기 싫으면 화면의 REFRESH 를 누른다.

6. Git 으로 바꾸기

k8s/deployment.yaml 의 replicas: 2 를 3 으로 고쳐 커밋·푸시한다.

sed -i 's/replicas: 2/replicas: 3/' k8s/deployment.yaml
git commit -am "파드 3개로" && git push

화면에서 REFRESH 를 누르면(또는 3분 안에) OutOfSync 로 바뀐다. APP DIFF 를 누르면 replicas: 2 → 3 차이가 보인다. SYNC 하면 파드가 세 개가 된다. 바꾼 기록은 GitHub 커밋 목록에 그대로 남았다. 이게 GitOps 의 일하는 방식이다.

7. 몰래 바꾸기 — 드리프트 잡아내기

누군가 Git 을 거치지 않고 클러스터를 직접 바꿨다고 해 보자.

kubectl -n cicd-hello scale deploy/cicd-hello --replicas=5

ArgoCD 화면이 곧 OutOfSync 가 되고, DIFF 에 "Git 은 3, 실제는 5" 가 보인다. 10편에서 "파일과 어긋난다"고만 했던 것을 ArgoCD 는 보여 준다. 지금은 자동 동기화가 꺼져 있어 알려 주기만 한다. SYNC 를 누르면 Git 대로 3 개로 돌아간다.

8. 자동 동기화 켜기 — automated · prune · selfHeal

argocd/application.yaml 의 syncPolicy 를 이렇게 바꾼다.

  syncPolicy:
    automated:
      prune: true      # Git 에서 지운 것은 클러스터에서도 지운다
      selfHeal: true   # 누가 클러스터를 손으로 바꾸면 Git 대로 되돌린다
    syncOptions:
      - CreateNamespace=true
kubectl apply -f argocd/application.yaml
git commit -am "자동 동기화 켜기" && git push
옵션켜면꺼져 있으면
automatedGit 이 바뀌면 SYNC 를 누르지 않아도 적용OutOfSync 로 알려만 줌
pruneGit 에서 파일을 지우면 그 오브젝트도 클러스터에서 지움Git 에서 지워도 클러스터에 남음 (화면에 "지워야 함" 표시)
selfHeal클러스터를 손으로 바꾸면 몇 초 안에 Git 대로 되돌림Git 이 바뀔 때만 맞춤

7번을 다시 해 본다.

kubectl -n cicd-hello scale deploy/cicd-hello --replicas=5
kubectl -n cicd-hello get deploy cicd-hello -w
NAME         READY   UP-TO-DATE   AVAILABLE
cicd-hello   3/5     5            3
cicd-hello   3/3     3            3        ← ArgoCD 가 Git 대로 되돌림

prune 도 확인해 본다. git rm k8s/service.yaml → 커밋·푸시 → 잠시 뒤 kubectl -n cicd-hello get svc 가 비어 있다. 확인했으면 git revert HEAD → 푸시로 되살린다. Service 가 다시 생긴다 — 이게 GitOps 의 되돌리기다.

selfHeal(자가 치유) — 10편의 쿠버네티스 자가 치유(죽은 파드 다시 띄우기)를 한 층 위로 올린 것. 쿠버네티스는 "Deployment 에 적힌 대로", ArgoCD 는 "Git 에 적힌 대로" 맞춘다.
prune(가지치기) — 정답지에 없는 것을 정리하는 것. 켜 두지 않으면 Git 에서 지운 옛 오브젝트가 클러스터에 쌓인다.

9. 되돌리기 — 두 가지 방법

방법어떻게언제
git revert (권장)매니페스트 저장소에서 문제 커밋을 revert → push. ArgoCD 가 따라간다평소. 되돌린 기록도 Git 에 남는다
ArgoCD 화면의 HISTORY AND ROLLBACK지난 동기화 목록에서 하나 골라 ROLLBACK급할 때. 자동 동기화가 꺼져 있어야 된다(켜져 있으면 곧 Git 대로 다시 덮인다). 끝나면 Git 도 맞춰 둬야 한다

비공개 저장소라면

실무의 매니페스트 저장소는 대개 비공개다. ArgoCD 에 읽기 권한을 준다. 화면 Settings → Repositories → + CONNECT REPO → 방식 HTTPS, 저장소 주소, 사용자 이름(GitHub 아이디), 비밀번호 칸에 읽기 전용 PAT(Contents: Read-only). CLI 로는: 

argocd repo add https://github.com/<내아이디>/cicd-hello-manifests.git \
  --username <내아이디> --password <읽기 전용 PAT>

자주 걸리는 것

증상원인과 해결
Too long: must have at most 262144 bytes설치할 때 --server-side 를 빠뜨렸다. 붙여서 다시 apply
상태 Unknown, ComparisonError … repository not found저장소 주소 오타, 또는 비공개 저장소인데 연결을 안 했다
app path does not existpath: k8s 인데 저장소에 그 폴더가 없다(푸시 안 함, 폴더 이름 다름)
Synced 인데 DegradedGit 의 이미지 태그가 Docker Hub 에 없다(오타). 파드를 눌러 EVENTS 를 본다
namespaces "cicd-hello" not foundCreateNamespace=true 를 빠뜨렸다
Git 을 바꿨는데 반응이 없다최대 약 3분 기다리거나 REFRESH. 다른 브랜치에 푸시하지 않았는지 (targetRevision: main)
10편에서 손으로 만든 앱과 섞임10편 끝에서 kubectl delete namespace cicd-hello 를 안 했다. ArgoCD 가 덮어쓰긴 하지만 헷갈리면 지우고 다시 SYNC
