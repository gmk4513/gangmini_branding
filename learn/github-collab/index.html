PRACTICE

GitHub 협업 기능 실습
— 이슈 · 리뷰 · 보호 규칙

실습 GitHub gh CLI 코드 리뷰 브랜치 보호 2026.10.28

git 명령은 내 컴퓨터 안의 일이고, 이 글은 GitHub 위에서 사람끼리 일하는 방법이다. 이슈로 할 일을 정하고, PR 로 고치고, 리뷰를 받고, 실수로 main 이 망가지지 않게 규칙을 건다. 연습 저장소 하나를 만들어 처음부터 끝까지 따라 한다. 웹 화면과 gh 명령을 같이 적었다. 편한 쪽으로 하면 된다.

0. 준비 — 연습 저장소

git 기본 실습에서 만든 git-practice 가 있으면 그걸 쓴다. 없으면 새로 만든다. 공개(public)로 만든다. 무료 계정에서 브랜치 보호 규칙은 공개 저장소에서만 걸 수 있다. 

gh auth status                      # 로그인 확인. 안 돼 있으면 gh auth login
gh repo create git-practice --public --add-readme --clone
cd git-practice

보이는 것: Created repository <내아이디>/git-practice on GitHub 가 나오고, 같은 이름의 폴더가 생긴다. 안에 README.md 하나.

1. 이슈 만들기 — 라벨, 담당자

할 일을 이슈로 먼저 적는다. 라벨은 종류(버그·기능·문서), 담당자는 누가 할지다.

gh label create docs --color 0E8A16 --description "문서 수정"
gh issue create --title "README 에 실행 방법이 없다" \
  --body "처음 온 사람이 무엇을 해야 하는지 모른다. 실행 방법 한 줄을 넣자." \
  --label docs --assignee @me

보이는 것: 이슈 주소(…/git-practice/issues/1)가 출력된다. 웹에서 열면 오른쪽에 라벨 docs 와 담당자(나)가 붙어 있다. gh issue list 로 목록을 보면 #1 이 보인다.

웹으로 하려면: 저장소 → Issues 탭 → New issue → 제목·본문 → 오른쪽 Labels, Assignees.

2. 고치고 PR 열기 — Closes #1

git switch -c docs/readme-run
echo "" >> README.md
echo "## 실행" >> README.md
echo "index.html 을 브라우저로 연다." >> README.md
git add README.md
git commit -m "README 에 실행 방법 추가"
git push -u origin docs/readme-run

gh pr create --title "README 에 실행 방법 추가" \
  --body "Closes #1

## 확인 방법
- README 를 열어 '실행' 칸이 보이는지"

보이는 것: PR 주소(…/pull/2)가 나온다. 이슈와 PR 은 번호를 같이 쓰기 때문에 2번이 된다. 웹에서 PR 을 열면 오른쪽 Development 칸에 이슈 #1 이 이어져 있다.

Closes #1 — PR 본문(또는 커밋 메시지)에 이렇게 적으면, 그 PR 이 기본 브랜치에 합쳐질 때 이슈 #1 이 자동으로 닫힌다. Fixes #1, Resolves #1 도 같다.

3. 리뷰하기 — 댓글, suggestion, 승인

PR 의 Files changed 탭에서 줄 번호 옆 + 를 누르면 그 줄에 댓글을 단다. 이때 아래처럼 쓰면 "이렇게 바꾸세요"를 코드로 제안할 수 있다. 

```suggestion
`index.html` 을 브라우저로 연다. (더블클릭)
```

보이는 것: 댓글에 바뀐 줄이 초록·빨강으로 보이고 Commit suggestion 버튼이 생긴다. PR 작성자가 누르면 그대로 커밋된다.

줄 댓글을 다 달았으면 오른쪽 위 Review changes 에서 셋 중 하나를 고른다.

선택뜻gh 명령
Comment의견만. 합치기를 막지도 허락하지도 않음gh pr review 2 --comment -b "…"
Approve합쳐도 된다gh pr review 2 --approve
Request changes고치기 전엔 안 된다gh pr review 2 --request-changes -b "…"

혼자 연습할 때 주의: GitHub 은 자기 PR 을 승인할 수 없다. Comment 는 되지만 Approve 와 Request changes 는 거절된다. 승인까지 해 보려면 친구 계정을 Settings → Collaborators 로 초대해 서로 리뷰하면 된다.

4. 합치기 — 세 가지 방법

gh pr merge 2 --squash --delete-branch
방법main 에 남는 것언제
Merge commit (--merge)브랜치 커밋 전부 + 합침 커밋 하나브랜치의 커밋 이력을 그대로 남기고 싶을 때
Squash (--squash)커밋 하나로 뭉쳐서PR 하나 = 커밋 하나. 회사에서 가장 흔하다
Rebase (--rebase)브랜치 커밋을 main 위에 하나씩 다시합침 커밋 없이 일자 이력을 원할 때

보이는 것: PR 이 보라색 Merged 가 되고, 이슈 #1 이 Closed 가 된다(Closes #1 덕분). 원격 브랜치도 지워진다. 내 컴퓨터는 git switch main && git pull 로 맞춘다.

5. 브랜치 보호 규칙 — main 을 지키기

회사 저장소의 main 에는 거의 항상 규칙이 걸려 있다. "PR 없이 바로 push 금지", "승인 1명 이상", "테스트 통과해야 합치기".

  1. 저장소 → Settings → Rules → Rulesets → New ruleset → New branch ruleset
  2. 이름 protect-main, Enforcement status 를 Active
  3. Target branches → Add target → Include default branch
  4. 규칙 체크:
    • Require a pull request before merging → Required approvals 1
    • Require status checks to pass (Actions 를 만든 뒤에 그 검사 이름을 고른다)
    • Block force pushes
  5. Create
git switch main
echo "직접 push 해 보기" >> README.md
git commit -am "main 에 바로"
git push

보이는 것: push 가 거절되고 GH013: Repository rule violations found 와 함께 "변경은 PR 로 해야 한다"는 내용이 나온다. 규칙이 동작한다. (확인했으면 git reset --hard origin/main 으로 그 커밋을 지운다.)

혼자 쓰는 저장소의 함정: 승인 1명을 걸면, 자기 PR 은 승인할 수 없으니 영영 못 합친다. 혼자라면 Required approvals 를 0 으로 두거나, ruleset 의 Bypass list 에 Repository admin 을 넣는다. 회사에서는 이 목록이 아주 짧게 관리된다.

6. CODEOWNERS — 리뷰어 자동 지정

파일 경로마다 "이 부분은 이 사람이 봐야 한다"를 적어 두면, 그 경로를 건드린 PR 에 리뷰 요청이 자동으로 간다. 

# .github/CODEOWNERS
# 기본: 전부 내가 본다
*            @내아이디
# docs 폴더는 문서 담당, .sql 파일은 DB 담당 (뒤에 적은 줄이 이긴다)
/docs/       @문서담당
*.sql        @db담당

보이는 것: 이 파일이 main 에 들어간 뒤 PR 을 열면, 오른쪽 Reviewers 에 해당 사람이 자동으로 들어간다(PR 작성자 본인은 빠진다). ruleset 에서 Require review from Code Owners 를 켜면 그 사람의 승인이 있어야 합쳐진다.

7. 이슈 · PR 템플릿

매번 같은 칸을 채우게 하는 파일 두 개. 둘 다 기본 브랜치에 있어야 동작한다.

# .github/ISSUE_TEMPLATE/bug.md
---
name: 버그 신고
about: 재현할 수 있게 적어 주세요
labels: bug
---
## 재현 단계
1.
## 기대한 것
## 실제로 일어난 것
## 환경 (기기 · 브라우저)
# .github/pull_request_template.md
## 무엇을
## 왜 (Closes #)
## 확인 방법
- [ ]
## 스크린샷

보이는 것: New issue 를 누르면 "버그 신고"를 고르는 화면이 나오고, 고르면 본문에 칸이 채워져 있다. 새 PR 본문에도 템플릿이 들어 있다. 명령으로는 gh issue create --template "버그 신고".

자주 쓰는 gh 명령 모음

하고 싶은 것명령
내게 걸린 이슈 · PR 한눈에gh issue status · gh pr status
이슈 보기 (댓글까지)gh issue view 1 --comments
남의 PR 을 내 컴퓨터로 받아 실행gh pr checkout 7
PR 변경 보기gh pr diff 7
PR 의 검사(CI) 결과gh pr checks 7
PR 에 댓글gh pr comment 7 -b "확인했어요"
브라우저로 열기gh pr view 7 --web
조건이 채워지면 자동 합치기gh pr merge 7 --squash --auto
