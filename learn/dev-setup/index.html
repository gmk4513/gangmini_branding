실습 VS Code 터미널 Git Bash Python 가상환경 2026.10.28

Git 실습과 코드 구조 실습은 전부 내 컴퓨터에서 한다. 웹사이트나 온라인 편집기가 아니다. 명령을 치는 곳은 VS Code 안의 터미널 하나로 통일한다. 윈도라면 그 터미널을 Git Bash 로 바꿔 둔다. 이 글은 실습 글들을 시작하기 전에 한 번만 해 두면 되는 준비다.

터미널 — 마우스 대신 글자로 컴퓨터에 명령하는 창. 실습 글의 git switch dev 같은 줄은 전부 여기에 친다.
셸(shell) — 터미널 안에서 명령을 알아듣는 프로그램. 윈도의 PowerShell·명령 프롬프트(cmd), Git 을 깔면 같이 오는 Git Bash, 맥의 zsh 가 모두 셸이다. 셸마다 몇몇 명령의 문법이 다르다.

실습 폴더 위치C:\dev\ (윈도) · ~/dev/ (맥). OneDrive·바탕 화면·한글 경로는 피한다 (아래)

1. 설치할 것 네 가지

프로그램어디서 받나메모
VS Codecode.visualstudio.com편집기 + 터미널. 설치 중 "PATH 에 추가"를 켜 둔다
Gitgit-scm.com윈도용 설치 파일에 Git Bash 가 같이 들어 있다. 맥은 터미널에 git 을 치면 설치 안내가 뜬다
Python 3.11 이상python.org윈도 설치 첫 화면의 "Add python.exe to PATH" 를 꼭 체크한다

VS Code 를 열고 왼쪽 확장(Extensions)에서 Python(Microsoft) 확장 하나만 깔아 둔다. 가상환경을 알아서 찾아 주고, 코드에 밑줄로 오류를 보여 준다.

2. 터미널을 Git Bash 로 (윈도만)

실습 글의 명령은 bash 문법으로 썼다. 대부분은 PowerShell 에서도 똑같이 되지만, 가상환경 켜기나 몇몇 줄이 다르다. 헷갈리지 않게 VS Code 터미널의 기본을 Git Bash 로 바꿔 둔다.

  1. VS Code 에서 Ctrl + Shift + P → Terminal: Select Default Profile 을 친다
  2. 목록에서 Git Bash 를 고른다
  3. Ctrl + `(숫자 1 왼쪽 키)로 터미널을 연다. 이미 열려 있던 건 휴지통 아이콘으로 닫고 새로 연다
  4. 줄 끝이 $ 로 끝나면 Git Bash 다. PowerShell 은 PS C:\...> 로 시작한다

3. 설치 확인

터미널에 한 줄씩 친다. 버전 숫자가 나오면 된다(숫자는 사람마다 다르다). 아래는 내 컴퓨터(윈도, Git Bash)에서 나온 것이다.

$ git --version
git version 2.47.0.windows.2

$ python --version
Python 3.11.6

$ code --version
1.140.0

$ gh --version
gh version 2.97.0 (2026-07-31)
이렇게 나오면원인과 해결
command not found · 인식되지 않습니다설치가 안 됐거나 PATH 에 없다. 다시 설치하면서 PATH 옵션을 켜고, VS Code 를 껐다 켠다 (켜져 있던 터미널은 새 PATH 를 모른다)
python 을 쳤더니 Microsoft Store 가 열린다윈도의 "앱 실행 별칭"이 가로챈 것. python.org 판을 PATH 옵션으로 다시 깔거나, 설정 → 앱 → 고급 앱 설정 → 앱 실행 별칭에서 python 을 끈다
맥에서 python 이 없다맥은 python3 · pip3 로 친다. 실습 글의 python 을 전부 python3 로 읽는다

4. Git 에 내 이름 알려 주기 (한 번만)

$ git config --global user.name "내이름"
$ git config --global user.email "GitHub에 등록한 이메일"
$ git config --global init.defaultBranch main
$ git config --global core.editor "code --wait"
  • 이름·이메일은 커밋마다 찍힌다. 공개 저장소에 진짜 이메일을 남기기 싫으면 GitHub → Settings → Emails 의 …@users.noreply.github.com 주소를 쓴다. 나도 공개 연습 저장소는 이 주소로 올렸다.
  • defaultBranch main 은 새 저장소의 첫 브랜치 이름을 main 으로 맞춘다. 실습 글이 전부 main 기준이다.
  • core.editor 는 git commit 을 -m 없이 쳤거나 git rebase -i 를 했을 때 열리는 편집기다. 이걸 안 하면 윈도에선 Vim 이 열려서 빠져나오는 법을 모르면 갇힌다.

5. 실습 폴더는 어디에

C:\dev\ 같은, 영어로 된 짧은 경로에 만든다. 바탕 화면·문서처럼 OneDrive 가 동기화하는 곳과 한글·띄어쓰기가 들어간 경로는 피한다. 실제로 겪은 일들이다.

  • 한글이 들어간 경로에서 안드로이드 빌드(Gradle)가 "파일 이름 구문이 잘못되었습니다"로 죽었다. 그래서 다이어리 앱은 C:\dev\ 에 사본을 두고 빌드한다.
  • OneDrive 폴더 안에서는 동기화가 파일을 잡고 있어서 폴더 이름 바꾸기가 "사용 중"으로 막히거나, 저장할 때 줄바꿈이 바뀌어 diff 가 통째로 바뀐 것처럼 보였다.
$ mkdir -p /c/dev        # Git Bash 에서 C:\dev 는 /c/dev 로 쓴다
$ cd /c/dev
$ git clone https://github.com/gmk4513/memo-api-practice.git
$ code memo-api-practice   # 그 폴더를 VS Code 로 연다

VS Code 가 새 창으로 그 폴더를 연다. 이후로는 그 창의 터미널에서 친다. 터미널은 열린 폴더에서 시작하므로 cd 를 따로 안 해도 된다. (VS Code 메뉴의 파일 → 폴더 열기로 열어도 같다.)

6. 가상환경 켜기 — 셸마다 다르다

파이썬 실습은 프로젝트마다 가상환경(venv)을 만든다. 프로젝트가 쓰는 라이브러리를 그 폴더 안의 .venv 에만 깔아서, 다른 프로젝트와 버전이 섞이지 않게 하는 것이다. 만드는 명령은 같고, 켜는 명령이 셸마다 다르다. 실습 글에서 가장 많이 막히는 곳이다. 

$ python -m venv .venv        # 만들기 (처음 한 번)
셸켜기
Git Bash (윈도)source .venv/Scripts/activate
PowerShell (윈도).venv\Scripts\Activate.ps1
명령 프롬프트 cmd (윈도).venv\Scripts\activate.bat
macOS · Linuxsource .venv/bin/activate

켜지면 프롬프트 앞에 (.venv) 가 붙는다. 그 상태에서 pip install -r requirements.txt 를 치면 이 프로젝트 안에만 깔린다. 끌 때는 deactivate. Git Bash 에서 실제로 켜 보고 확인한 결과다(경로만 실습 폴더 기준으로 바꿔 적었다). 

$ python -m venv .venv
$ source .venv/Scripts/activate
(.venv) $ python -c "import sys; print(sys.prefix)"
C:\dev\memo-api-practice\.venv          ← 가상환경 안의 파이썬이 잡혔다
(.venv) $ deactivate
  • PowerShell 에서 "스크립트를 실행할 수 없으므로" 가 뜨면 실행 정책 때문이다. Set-ExecutionPolicy -Scope CurrentUser RemoteSigned 를 한 번 치거나, 그냥 Git Bash 를 쓴다.
  • VS Code 가 가상환경을 모른다면 Ctrl + Shift + P → Python: Select Interpreter → .venv 가 들어간 항목을 고른다. 그러면 새로 여는 터미널마다 저절로 켜진다.
  • .venv 폴더는 저장소에 올리지 않는다. 연습 저장소의 .gitignore 에 이미 들어 있다.

PATH — 터미널이 git·python 같은 이름을 쳤을 때 실행 파일을 찾아보는 폴더 목록. 설치는 됐는데 "명령을 찾을 수 없다"면 대개 여기에 안 들어간 것이다.
가상환경(venv) — 프로젝트 폴더 안에 둔 그 프로젝트 전용 파이썬과 라이브러리 묶음. 켜 둔 동안만 python·pip 가 그걸 가리킨다.

여기까지 되면 어느 실습 글이든 바로 따라 할 수 있다. Git 이 처음이면 Git 첫걸음부터, 코드 구조를 해 보려면 브랜치 따서 계층 + DI 로 정리하기로 간다.

이어서

  • Git 첫걸음 — 저장소 만들고 커밋하기

  • ES 모듈과 클래식 스크립트 — 왜 어떤 프로젝트는 서버를 띄워야만 열리나
